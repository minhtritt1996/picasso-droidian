## 3. Phát hiện chi tiết

### 3.1 🔴 Wi-Fi hỏng — chuỗi nguyên nhân đã xác định rõ

Trạng thái máy: `wlan0` không tồn tại; `k30-wifi.service` fail với
`"wlan character device not found in /proc/devices"`; `lsmod` chỉ có `adspboot`.

Chuỗi nhân quả:

1. `CONFIG_QCA_CLD_WLAN=m` trong `kernel/out_halium/.config` → Wi-Fi **không** built-in,
   buộc phải `insmod` module đúng.
2. `k30-wifi-init.sh` (cả trong repo và trên máy) lại chạy
   `modprobe wlan || insmod /lib/modules/$(uname -r)/kernel/drivers/staging/qcacld-3.0/wlan.ko`
   — trong khi thư mục module hiện tại **không có** `wlan.ko` (chỉ còn ở dir cũ
   `4.19.113-lineage-g23233c911-dirty/`). Script **chưa bao giờ được cập nhật** sang `wlan_cld3`.
3. Ngay cả khi sửa script trỏ `wlan_cld3`, module đóng gói vẫn **không load được**:
   vermagic (xem 3.3) không khớp kernel đang chạy.

Đối chiếu tài liệu: `docs/08-wifi-bringup-tested.md` + `docs/STATUS-wifi-ds.md` mô tả
flow hoạt động thật là `picasso-wifi.service`/`picasso-wifi.sh` + `logkstub.ko` +
`qca_cld3_wlan.ko` vermagic-patched + chờ FW 30s + `autoconnect=no`. Nhưng các file này
**không nằm trong git/package** ("phone-side files, NOT in git"), còn `postinst` của v1.1.0 lại
**mask `picasso-wifi.service`** và enable `k30-wifi.service` (bản hỏng). → v1.1.0 là regression Wi-Fi.

**Hướng sửa (khuyến nghị):**
- (a) Chốt lại driver thắng: `wlan_cld3.ko`; sửa `k30-wifi-init.sh` load đúng tên module.
- (b) Build lại module theo kernel hiện tại (xem 3.3), đặt vào `/lib/modules/<release>/updates/`.
- (c) Thêm chờ FW-ready + settle 30s sau `lxc@android` (bài học "insmod sớm = reset SoC").
- (d) Giữ `autoconnect=no` cho profile Wi-Fi, hoặc xác nhận lại đã an toàn rồi bật.
- (e) Gỡ hẳn `picasso-wifi.*` khỏi máy hoặc đưa vào package — đừng để 2 flow song song.

### 3.3 🔴 Lệch phiên bản kernel ↔ module (nguyên nhân gốc của 3.1 và lỗi BT/audio tiềm ẩn)

- Kernel đang chạy: `4.19.113-lineage-g5f44e3254-dirty`; `CONFIG_MODVERSIONS=y`,
  `CONFIG_LOCALVERSION="-lineage"`, `CONFIG_LOCALVERSION_AUTO=y` (2 dòng cuối là **thay đổi chưa commit**
  trong `kernel/picasso_defconfig`; bản đã commit là `"-lineage-picasso"` + AUTO **off**).
- Vermagic từng module đóng gói:
  - `updates/wlan_cld3.ko` → `4.19.113-lineage-gc8849ed3e SMP preempt mod_unload aarch64` (bản cũ, **không** modversions)
  - `updates/hci_vhci.ko`, `logkstub.ko` → `4.19.113-lineage-picasso+ …`
  - `updates/adspboot.ko` → `4.19.113-lineage-g5f44e3254 … modversions`
  - → **không bản nào khớp** `…-g5f44e3254-dirty … modversions`.
- Hệ quả: BT chỉ còn sống nhờ `CONFIG_BT_HCIVHCI=y` built-in; mọi module out-of-tree
  (wifi/audio/BT-vhci/logkstub) hỏng theo mỗi lần kernel bump commit.
- `DEBIAN/postinst` còn hard-code `ln -snf /lib/modules/4.19.113-lineage-picasso+ /lib/modules/$CURRENT_KVER`
  → với AUTO suffix, mỗi build tạo một symlink rác mới (hiện máy có 3 symlink `-g23233c911-dirty`,
  `-g382384936-dirty`, `-g5f44e3254-dirty`).

**Hướng sửa:**
- Trong `picasso_defconfig`: trả về `CONFIG_LOCALVERSION="-lineage-picasso"`, tắt `LOCALVERSION_AUTO`
  (release ổn định giữa các lần build) — hoặc chấp nhận AUTO nhưng phải commit sạch trước khi build
  và build lại **tất cả** module mỗi lần.
- `kernel/build_kernel.sh`: bổ sung target `modules`, copy `*.ko` vào package
  (hiện script chỉ build `Image.gz dtbs` — không bao giờ sinh module).
- Thống nhất `CONFIG_MODVERSIONS` (README/docs ghi "off", config đang `y`).
- postinst: bỏ hard-code, dùng `$(uname -r)` + depmod đúng release.

### 3.4 🟠 Hai script build boot cũ dùng layout sai (nguy cơ flash ảnh chết)

`docs/02-boot-image-layout.md` ("PROVEN, do not deviate") và `scripts/pack_boot.sh` dùng:

- ramdisk offset `0x1200000`, DTB offset `0x1728000` (và có `rec-picasso.dtb`).

Nhưng `build_halium_local.sh` và `build_halium_picasso.sh` vẫn dùng **`0x01000000` / `0x01f00000`**
— tài liệu ghi rõ `0x1000000` bị kernel 48MB đè lên ramdisk → **không boot**. Hai script còn:
- không apply patch kernel, không build `modules`;
- khác nhau về config (bản `local` có thêm `COMPAT_VDSO off`, sed NT36/ION, `USB_CONFIGFS_ECN`…; bản `picasso` thiếu) → dễ chọn nhầm.

**Hướng sửa:** xoá 2 script (hoặc gộp còn 1 + sửa offset theo `pack_boot.sh`).
`README.md` nên trỏ duy nhất về `kernel/build_kernel.sh` + `scripts/pack_boot.sh` (đang đúng).

## Follow-up v1.2.1 (cùng ngày, sau reboot kiểm tra end-to-end)

1. **android-mount chạy 2 lần/boot:** unit oneshot không `RemainAfterExit`
   nên bị kéo chạy lại; các dòng `ExecStartPost` bind file overlay bị chồng
   lên nhau và kernel tạo thêm **self-mount trên chính file nguồn** →
   dpkg về sau không thay được file (`cannot make backup link ... Invalid
   cross-device link` / `target is busy`). Sửa: thêm `RemainAfterExit=yes`
   + mỗi bind có guard `grep -qF " <đích> " /proc/self/mountinfo ||` (chỉ
   mount khi chưa có), chạy lại vô hại.
2. **Vendor rc mode 664:** dpkg giữ nguyên mode từ archive nên
   `android.hardware.memtrack@1.0-service.rc` thành group-writable → init
   bỏ qua file ("Skipping insecure file"). Sửa: chuẩn hoá mode khi build
   deb (`find ... chmod 644/755`) + postinst `chmod 644 *.rc` phòng hờ.
3. **android_boot_completed bị treo:** `setprop` trong container trúng một
